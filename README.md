# GOS GRUB Manager

GOS GRUB Manager is a GTK 4/libadwaita application for Linux that discovers
existing GRUB boot entries on supported disks and manages selected
configurations in its own `custom.cfg`.

> **Warning:** The scan reads GRUB configurations from disks. GRUB scripts
> can contain commands. Only import configurations from trusted disks and
> inspect the generated files before restarting your computer.

## Features

- Finds supported Linux GRUB configurations, including on unmounted disks,
  and imports recognized boot entries. The running system's GRUB
  configuration is excluded.
- Checks Windows boot managers on EFI system partitions against the BCD and
  required Windows files. Legacy BIOS is not supported.
- Displays discovered configurations and notes; their order can be changed
  before saving.
- Opens previously saved configuration files in the logged-in user's text editor.
- Does not modify `grub.cfg`. Files are written only after confirmation, and
  only under `/boot/grub/custom` and `/boot/grub/custom.cfg`.

## Requirements

- Linux with GRUB and a graphical session (X11 or Wayland)
- Python 3.9 or newer
- PyGObject, GTK 4 and libadwaita
- `pkexec`, `dbus-run-session`, `runuser`, `lsblk`, `findmnt`, `mount`,
  `umount` and `grub-script-check`
- Filesystem drivers for the disks to be scanned
- For Windows UEFI detection, the Python 3 bindings for HiveX (for example
  `python3-hivex`) and `ntfs-3g`

Install the required system packages using your distribution's package
manager. Package names and layouts vary by distribution.

## Starting

Run from the project directory:

```sh
./start.py
```

On Debian, install the package and launch **GuideOS GRUB Manager** from the
applications menu, or run `gos-grub-manager`.

The launcher requests administrator privileges using `pkexec`. It does not
install a custom polkit rule. The graphical session must allow the privileged
process to access the display. Alternatively, run `/usr/bin/python3 start.py`.

The manager uses a private D-Bus session bus. The editor is launched without
administrator privileges in the logged-in user's context. If the accessibility
bus is unavailable, accessibility may be limited; the application reports this.
The launcher reads the user's light or dark appearance preference from the
desktop settings portal, with GNOME settings as a fallback, and passes it to
the manager. The preference is read at startup; restart the manager after
changing it. If no preference can be determined, libadwaita uses its default.

## Usage

1. Start the application and select **Search**.
2. Review the discovered entries and notes. New results are appended to the order.
3. Adjust the order with **Move up** and **Move down** if needed. Double-click
   an existing saved file to open it in the default editor.
4. Select **Add to custom.cfg** and confirm saving.

Scanning does not save anything. Temporary read-only mounts may be used.
Existing mounts are not unmounted. If unmounting fails, the application reports
the affected mount point; check it manually if necessary.

Before saving, generated files are checked for syntax using
`grub-script-check`. Files in the `custom` subdirectory are sourced from
`/boot/grub/custom.cfg` using `${prefix}`. Other existing `.cfg` files in this
directory are retained and also included in the order. This includes
previously saved copies of the running system's configuration; they are not
removed automatically.

Unmanaged `custom.cfg` files and unmanaged target files with the same name are
not overwritten. If the files or their order have changed externally since
startup, restart the application. Unverified Windows files generated by the
manager are no longer included when saving, but are not deleted.

## Limitations and security

- Supported GRUB files are sought at `boot/grub/grub.cfg`,
  `@/boot/grub/grub.cfg`, and `grub/grub.cfg` on separate boot partitions.
  Btrfs is additionally mounted with `subvolid=5`
  to access the `@` subvolume. The scan uses `rescue=nologreplay` to prevent
  log replay and retries with the older `nologreplay` option if mounting fails.
- Unknown filesystems, unopened encrypted devices, and configurations with
  unresolved external GRUB variables cannot be imported. Submenus are
  processed as individual entries; outer conditions and global settings are
  not copied. The literal `linux_gfx_mode` setting in the standard Debian
  `10_linux` header is copied into each entry; dynamic or ambiguous values
  remain unsupported.
- Windows verification covers UEFI boot managers on FAT EFI partitions. The
  BCD must unambiguously reference GPT/NTFS partitions; required bootloader and
  system files must exist and be readable. Successful verification confirms an
  installation exists, but does not guarantee it will boot.
- Imported entries are copies. Search again after kernel or GRUB updates.
  `grub-script-check` checks syntax, not actual bootability. Behavior also
  depends on the existing GRUB configuration and available GRUB modules.
- The project neither uses `os-prober` nor modifies `grub.cfg`. A forced
  process termination or system failure during a scan may leave a temporary
  mount behind.

## Translations

English is the source language. A German gettext catalog is included; the
launcher passes the user's locale to the privileged application and editor.
An unsupported language falls back to English.

To update translations after changing source messages, run:

```sh
xgettext --language=Python --from-code=UTF-8 --package-name="GOS GRUB Manager" \
  --keyword=_ --keyword=tr \
  --keyword=ngettext:1,2 -o locale/gos-grub-manager.pot \
  app.py grub_manager.py windows_uefi.py open_editor.py start.py
msgmerge --update locale/de/LC_MESSAGES/gos-grub-manager.po locale/gos-grub-manager.pot
msgfmt --check -o locale/de/LC_MESSAGES/gos-grub-manager.mo \
  locale/de/LC_MESSAGES/gos-grub-manager.po
```

Translate new or fuzzy entries in the `.po` file before running `msgfmt` and
commit the compiled `.mo` alongside it. Generated GRUB scripts use fixed
English messages rather than translations so that catalog text cannot alter
GRUB syntax.

## Development and tests

Tests use temporary directories and simulated mount commands. They do not
change `/boot` or the running system's mounts.

```sh
/usr/bin/python3 -m unittest discover -s tests -v
```

## Debian package

Build the binary package from the project root with Debian packaging tools
installed (`debhelper` and `gettext`):

```sh
dpkg-buildpackage -us -uc -b
```

The `.deb` is written to the parent directory. Install it with:

```sh
sudo apt install ../gos-grub-manager_0.1.0-1_all.deb
```

`python3-hivex` and `ntfs-3g` are recommended for Windows UEFI detection.
